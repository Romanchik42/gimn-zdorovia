### **БЛОК 0: Фикс "Сохранить картинку" в "Поделиться" (перевёрнутая логика)**

**Симптом от Романа:** кнопка "Сохранить картинку" открывает системный share sheet ("Отправить кому-то"), а не сохраняет напрямую в галерею.

**Причина:** в блоке 0 GIMN-029 кот сделал share sheet **основным путём** (с прицелом на iOS/Telegram WebView, где скачивание запрещено). Но получилось перевёрнуто — все платформы теперь показывают share sheet вместо сохранения.

**Правильная логика:**
1. **Сначала пробовать прямое скачивание** через `<a download>` + blob (Chrome, Firefox, Edge — работает)
2. **Если браузер игнорирует download** (iOS Safari, Telegram WebView) — тогда fallback на share sheet
3. **Кнопка "Не сохранилось?"** — как сейчас (показывает картинку для долгого нажатия)

**Детект браузера:**
```typescript
const supportsDirectDownload = () => {
  // Простой тест: <a download> работает где угодно кроме iOS Safari
  const a = document.createElement('a');
  return typeof a.download !== 'undefined' && 
         !/iPad|iPhone|iPod/.test(navigator.userAgent) &&
         !window.Telegram?.WebApp; // Telegram WebView тоже игнорирует
};

const handleSave = async () => {
  if (supportsDirectDownload()) {
    // Прямое скачивание
    const canvas = qrCanvasRef.current;
    canvas.toBlob(blob => {
      const url = URL.createObjectURL(blob);
      const a = document.createElement('a');
      a.href = url;
      a.download = 'gimn-zdorovia-qr.png';
      document.body.appendChild(a);
      a.click();
      document.body.removeChild(a);
      setTimeout(() => URL.revokeObjectURL(url), 1000);
    }, 'image/png');
  } else {
    // Fallback: share sheet
    await shareViaWebShareAPI();
  }
};
```

**Проверка на реальных устройствах:**
- Desktop Chrome/Firefox/Edge → **прямое скачивание** (файл в Загрузках)
- Android Chrome → **прямое скачивание** (файл в Загрузках)
- iOS Safari → **share sheet** (кнопка "Сохранить в Фото")
- Telegram WebView (мобиль) → **share sheet** ("Сохранить в Фото")

В отчёт: **на каком устройстве что видел**.
