# Анализ проекта «Гимн.здоровья»

## 1. Общая оценка

Проект представляет собой зрелое PWA + Telegram-бот приложение для реабилитации при болезни Бехтерева и общей физической формы. Техническая спецификация (v2.0 с дополнениями D.1–D.12) подробна, архитектура продумана, бизнес-логика (адаптация, Decision Tree, реферальная система) описана детально. Медицинская база из 76 упражнений с противопоказаниями и вопросами к врачу — сильная сторона. Документ о пути к самостоятельному приложению (домен, PWA, магазины) показывает понимание продукта.

Однако для выхода на рынок врачей и компаний есть ряд недочётов, ошибок и рисков, которые стоит устранить.

## 2. Выявленные ошибки и несоответствия

### 2.1. Технические и логические

1. **Противоречие между v2.0 и D.1 по аутентификации.**  
   В v2.0 (раздел 0.3) заявлены Telegram Login Widget + Email/Password. В D.1 сказано, что email-формы удалены, вход только через Telegram. Нужно проверить, действительно ли email-вход убран из кода, или остались артефакты. Для врачей и корпоративных пользователей email-вход может быть критичен.

2. **Адаптация тренировок (D.3) не учитывает причину пропуска.**  
   Упражнения с ≥2 отметками ❌/⚠️ заменяются на аналоги. Но ❌ может означать «не хочу», а ⚠️ — «плохо» (побочка). Стоит различать: заменять только при ⚠️ (побочка) или при ❌, если пользователь указал причину «не могу выполнить».

3. **Общий прогресс для двух режимов (D.7) может быть неинформативным.**  
   Вес, скованность и тест Шобера — разные показатели для Бехтерева и общей формы. Лучше фильтровать графики по активному режиму или показывать отдельные вкладки.

4. **Смена ответа про турник (D.9) удаляет только неначатую тренировку.**  
   Если тренировка уже начата, что происходит? Не описано. Нужно либо предупреждать, либо доигрывать текущую.

5. **Cron-job.org — внешний риск.**  
   Для напоминаний и отчётов используется сторонний сервис. Vercel предоставляет собственный Cron Jobs (входит в тариф), это надёжнее и проще в поддержке.

6. **Публичный бакет для аватаров (D.6).**  
   «Публичное чтение» означает, что любой, зная URL, может получить фото. Для медицинского приложения лучше приватный бакет с подписанными URL.

7. **Не описан сценарий отказа от режима.**  
   Пользователь может активировать два режима, но как деактивировать один? В D.7 сказано, что переключение между активными, но нет кнопки «отказаться от режима».

8. **Каталог упражнений (D.12) показывает все упражнения, но в тренировке дня фильтр по режиму.**  
   Пользователь может увидеть упражнение в каталоге, но не найти его в своей программе. Нужна подсказка: «Это упражнение доступно в режиме X».

9. **Отсутствует обработка ошибок при генерации меню (Edge Case 15).**  
   «Меню в разработке» — слабое решение. Лучше предложить ручной выбор блюд из доступных или упрощённый рацион.

10. **Не описан механизм обновления базы упражнений без деплоя.**  
    Админ добавляет упражнение через Supabase Studio. Но как оно попадает в кеш PWA? Нужен механизм инвалидации или версионирования.

### 2.2. Медицинские и юридические

1. **Отсутствует политика конфиденциальности и согласие на обработку ПДн.**  
   Приложение собирает медицинские данные (диагностика Бехтерева, побочки). Это требует явного согласия и соответствия 152-ФЗ. В спецификации упомянут только дисклеймер, но не юридические документы.

2. **Не решён вопрос, является ли приложение медицинским изделием.**  
   Если оно рекомендует упражнения при заболевании, это может подпадать под regulation. Нужна консультация юриста. Возможно, позиционирование как «wellness» снимет вопрос, но для врачей это важно.

3. **Валидация врачами не подтверждена.**  
   Документ для врача — отличный шаг, но нет информации, что хотя бы один ревматолог проверил упражнения. Для предложения клиникам это необходимо.

4. **Дисклеймер есть, но его недостаточно.**  
   Нужно добавить: «Приложение не является медицинским изделием и не подлежит регистрации» (если это так), а также ссылку на политику обработки данных.

### 2.3. UX/UI

1. **Онбординг может быть перегружен.**  
   В D.6 добавлена углублённая диагностика (22 вопроса). Это увеличивает путь до первой тренировки. Стоит сделать её опциональной и предлагать после первого занятия.

2. **Тур (US-11) запускается только один раз.**  
   Хорошо, но если пользователь пропустил, он может забыть, как вернуться. Кнопка «Показать тур заново» в настройках есть — это ок.

3. **Звуки (D.7) синтезируются скриптом.**  
   Это не ошибка, но стоит проверить, как они звучат на разных устройствах. Возможно, предложить пользователям выбор из готовых наборов.

4. **Реферальная система (US-12) не имеет наград.**  
   В MVP это задел, но для роста виральности стоит добавить хотя бы символические бонусы (например, разблокировка дополнительных упражнений за приглашённых).

## 3. Рекомендации и дополнения

### 3.1. Для повышения доверия врачей

- **Провести пилотное тестирование с 2–3 ревматологами.** Дать им доступ к админ-панели, чтобы они могли назначать программу пациенту и отслеживать прогресс. Это создаст кейсы.
- **Добавить в документ для врача ссылки на конкретные пункты ASAS/EULAR.** Например: «Упражнение соответствует рекомендации ASAS/EULAR 2022, раздел 4.2».
- **Создать личный кабинет врача.** Врач вводит email пациента, назначает режим и видит отчёты. Это повысит ценность для клиник.
- **Юридическая чистота:** опубликовать политику конфиденциальности, добавить чекбокс согласия при регистрации, описать, как хранятся данные (шифрование, сроки).

### 3.2. Для B2B (компании)

- **Корпоративный велнес:** предложить компаниям пакет «Здоровье сотрудников» — доступ к приложению по промокоду, админ-панель для HR с агрегированной статистикой (без персональных данных).
- **Интеграция с программами мотивации:** например, за 10 тренировок в месяц — бонус от компании. Это можно реализовать через API.
- **Добавить роль «менеджер компании»** с ограниченным доступом к статистике своих сотрудников.

### 3.3. Технические улучшения

- **Заменить cron-job.org на Vercel Cron Jobs** (или Supabase Edge Functions с планировщиком). Это снизит риск отказа внешнего сервиса.
- **Сделать бакет аватаров приватным** с подписанными URL.
- **Добавить версионирование базы упражнений** для корректного обновления PWA-кеша.
- **Реализовать различие между ❌ и ⚠️** при адаптации: ⚠️ — побочка, ❌ — пропуск. Заменять только при ⚠️, а при ❌ спрашивать причину.
- **Добавить механизм деактивации режима** (кнопка «Больше не занимаюсь этим режимом»).

### 3.4. Монетизация

- **Freemium:** базовые функции (тренировка дня, меню) бесплатно; расширенные (конструктор, углублённая диагностика, персональные отчёты) — по подписке.
- **Лицензии для клиник:** годовая подписка на клинику с возможностью назначать программы пациентам.
- **Партнёрские программы:** рекомендации товаров (витамины, коврики) с комиссией.
- **B2B-велнес:** продажа корпоративных пакетов.

## 4. Выводы

Проект имеет сильную техническую и медицинскую базу, но для выхода на рынок врачей и компаний необходимо:
1. Закрыть юридические вопросы (ПДн, статус медизделия).
2. Провести валидацию с врачами и получить хотя бы один подтверждающий отзыв.
3. Добавить B2B-функционал (кабинет врача, админ-панель для HR).
4. Продумать монетизацию.
5. Устранить выявленные технические недочёты.

После этого приложение можно уверенно предлагать как дополнительный инструмент для реабилитации и корпоративного велнеса.
