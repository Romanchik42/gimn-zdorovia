#### 0.1 Кнопка "Сохранить картинку" — не сохраняет

**Симптом (со скрина Романа):**
На мобиле есть кнопка "⬇ Сохранить картинку" — при клике ничего не происходит. QR не скачивается.

**Причина (гипотеза):**
Вероятно используется `<a download>` с data-URI SVG — на iOS Safari и в WebView Telegram это часто не работает. Или canvas.toDataURL без обработки клика.

**Решение:**
1. QR рендерится как canvas (или конвертить SVG → canvas → PNG)
2. По клику "Сохранить картинку":
   - Canvas → `toBlob('image/png')`
   - `URL.createObjectURL(blob)` → создать временную ссылку
   - Программный клик по `<a download="gimn-zdorovia-qr.png">`
   - `URL.revokeObjectURL` через таймаут

```tsx
const handleSave = async () => {
  try {
    const canvas = qrCanvasRef.current;
    if (!canvas) return;
    
    canvas.toBlob((blob) => {
      if (!blob) return;
      const url = URL.createObjectURL(blob);
      const a = document.createElement('a');
      a.href = url;
      a.download = 'gimn-zdorovia-qr.png';
      document.body.appendChild(a);
      a.click();
      document.body.removeChild(a);
      setTimeout(() => URL.revokeObjectURL(url), 1000);
    }, 'image/png');
  } catch (e) {
    // Fallback для мобильных Safari / Telegram WebView:
    // показать модалку "Долгое нажатие на QR → Сохранить в фото"
    setShowManualSaveHint(true);
  }
};
```

**Fallback:** если браузер не поддерживает download (iOS Safari, Telegram in-app browser) — показать подсказку "Нажмите и удерживайте QR-код → выберите 'Сохранить в фото'".

**Проверка на мобиле:** iPhone Safari + Telegram in-app browser + Android Chrome.

### **БЛОК 0-TOUR: Переделка онбординг-тура**

#### Общие правила тура (для всех шагов)

1. **Кнопка "Начать" на главной приглушена** пока идёт тур — блёкло-серая, некликабельная, чтобы не отвлекала от подсказок. Возвращается в активный вид на последнем шаге тура (или по "Пропустить тур").

2. **Подсказка перенесена наверх** и увеличена — крупнее текст, шире карточка, помещается больше информации.

3. **Кнопки в один ряд** внизу подсказки:
   ```
   [ Пропустить тур ]  [ Назад ]  [ Дальше → ]
   ```
   - "Пропустить тур" — левая, вторичная (outline/тонкая рамка)
   - "Назад" — центр, вторичная
   - **"Дальше →"** — правая, **главная** (яркая заливка, крупнее, привлекает внимание)

4. **Каждый шаг тура открывает реальный экран** — пользователь видит функцию в действии, а не только подсказку.

#### E2. SMS вход

Файлы: `src/lib/auth/sms.ts`, `src/app/api/auth/sms/request/route.ts`, `src/app/api/auth/sms/verify/route.ts`

**Провайдер:** SMSC.ru (популярный в РФ) или SMS.ru — оставляю выбор коту.

**Логика:**
1. Пользователь вводит номер (в формате +7...)
2. POST `/api/auth/sms/request` → отправляет код на номер
3. Пользователь вводит код (6 цифр)
4. POST `/api/auth/sms/verify` → проверяет, создаёт сессию

**Плейсхолдер если ключа нет:**
- ENV переменная: `SMS_PROVIDER_KEY` (не задана → SMS вход показывает "временно недоступен")
- В логах не светить ключ

**Миграция 0027** (создать таблицу для OTP):
```sql
CREATE TABLE IF NOT EXISTS auth_otp (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  identifier TEXT NOT NULL,  -- телефон или email
  code_hash TEXT NOT NULL,   -- bcrypt хэш, не сам код
  channel TEXT NOT NULL CHECK (channel IN ('sms', 'email')),
  attempts INTEGER DEFAULT 0,
  expires_at TIMESTAMPTZ NOT NULL,
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_otp_identifier ON auth_otp(identifier);

-- Автоочистка: индекс на expires_at + cron удаления
CREATE INDEX IF NOT EXISTS idx_otp_expires ON auth_otp(expires_at);
```

**Ограничения:**
- Не более 3 попыток на одну заявку
- Не более 3 заявок с одного номера в час
- Код действителен 5 минут

#### E3. Email вход

Аналогично SMS, но:
- Провайдер: **Resend** (проще) или **SMTP-сервис** (Mailgun/SendGrid)
- Тот же алгоритм: код на email → верификация → сессия
- ENV переменная: `EMAIL_PROVIDER_KEY`

Использует ту же таблицу `auth_otp` (channel='email').

#### E4. Google / Apple / VK Sign-In

**НЕ полная реализация**, а **скелеты**:
- Кнопки видны в UI
- При клике — редирект на страницу-заглушку "Скоро будет доступно"
- ENV переменные — плейсхолдеры (`GOOGLE_CLIENT_ID`, `APPLE_CLIENT_ID`, `VK_APP_ID`)

**Причина отсрочки:** каждый OAuth требует регистрации приложения на стороне провайдера (Google Console, Apple Developer, VK App). Это работа Романа с личными аккаунтами. Батч подготавливает почву — скелеты + документация в README, как включить.

#### E5. Страховки на каждом канале

Правило Романа: "если не сработает кнопка — страховка". На каждом способе:

- **Telegram:** уже есть "Кнопка не открылась? Откройте бота в Telegram"
- **SMS:** "Не пришёл код? Попробовать снова через 60 сек" + "Написать в поддержку"
- **Email:** "Не пришло письмо? Проверьте спам" + "Написать в поддержку"
- **OAuth (Google/Apple/VK):** "Не работает вход? Попробуйте через Telegram/SMS/Email"

Все кнопки "Написать в поддержку" ведут в форму отзыва в приложении (уже есть).
