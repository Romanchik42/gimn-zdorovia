# Путь к самостоятельному приложению

Что уже сделано, что осталось и во что это обойдётся, если захотеть, чтобы
«Гимн.здоровья» жил на своём адресе и ставился на телефон как обычное
приложение.

---

## 1. Что такое «самостоятельное приложение»

Три разные вещи, которые часто путают.

**Обычный сайт.** Открывается в браузере, сверху адресная строка, вкладка
теряется среди других. Так приложение выглядит сейчас, если открыть его
ссылкой.

**Устанавливаемое веб-приложение (PWA).** Тот же самый код, но телефон
предлагает «добавить на главный экран». После этого у него свой ярлык, оно
открывается на весь экран без адресной строки и частично работает без сети.
Пользователь не отличает его от обычного приложения, пока не полезет
проверять. **Это состояние у нас уже готово** — см. раздел 3.

**Приложение из магазина** (App Store, Google Play). Отдельная сборка,
отдельные правила, ежегодная плата Apple, проверка при каждом обновлении.
Сейчас не нужно — см. раздел 6.

---

## 2. Что нужно, чтобы был свой адрес

Сейчас приложение живёт по адресу вида `gimn-zdorovia.vercel.app`. Он рабочий
и бесплатный, но выглядит как черновик и привязан к чужому имени.

Чтобы получить свой, нужны три вещи, и две из них уже есть:

| Что | Состояние | Цена |
|---|---|---|
| Хостинг | **Есть** — Vercel | бесплатный тариф хватает |
| Сертификат HTTPS | **Есть** — Vercel выпускает Let's Encrypt сам | бесплатно |
| Домен | нужно купить | 200–1500 ₽ в год |

Про сертификат отдельно: покупать его не надо и настраивать не надо. Vercel
выпустит и будет продлевать сам, как только домен к нему привяжут. Это
важно, потому что без HTTPS телефон не разрешит установку на главный экран.

**Про имя домена.** `.ru` дешевле и понятнее российскому пользователю,
`.com` дороже и универсальнее. Регистратор — любой (reg.ru, timeweb,
beget); на цену влияет не он, а зона.

## 3. Что уже готово в коде

Проверено по состоянию на GIMN-016.

- **`public/manifest.json`** — паспорт приложения для телефона. Есть имя,
  описание, `display: standalone` (открывается без адресной строки),
  `start_url: /app`, книжная ориентация, цвета, три иконки (192, 512 и
  «маскируемая» 512 для круглых ярлыков Android), иконка для iPhone,
  три ярлыка быстрого доступа (тренировка, меню, прогресс).
- **`public/sw.js`** — service worker. Написан руками, потому что готовая
  библиотека `next-pwa` с Next 16 не работает. Что он делает: статику
  отдаёт из кеша, страницы главной и тренировок сохраняет при заходе, без
  сети показывает последнюю сохранённую или страницу «нет сети», данные
  пользователя (`/api/*`) не кеширует никогда.
- **Работа без сети** — отметки ✅/⚠️/❌ складываются в память браузера и
  уходят на сервер, когда связь возвращается.
- **Иконки и ярлык** — `public/icons/`, генерируются `scripts/generate-icons.mjs`.

**Чего не хватает для витрины установки.** В манифесте нет раздела
`screenshots` — из-за этого Android показывает короткое окно установки
вместо большого с картинками. Это не мешает установке, но выглядит беднее.
Нужны 2–3 скриншота реального приложения (главная, тренировка, меню)
размером 1080×1920; сделать их можно только с работающего приложения
с живыми данными.

## 4. Порядок действий с доменом

Полчаса работы, из которых 25 минут — ожидание.

1. **Купить домен** у любого регистратора.
2. **Добавить его в Vercel**: проект → Settings → Domains → Add. Vercel
   покажет, какие записи DNS прописать.
3. **Прописать записи DNS** в панели регистратора — обычно это `A` на адрес
   Vercel и `CNAME` для `www`. Vercel даёт точные значения, придумывать
   ничего не надо.
4. **Подождать.** Обычно 10–30 минут, изредка до суток. Vercel сам покажет
   галочку, когда домен заработает, и сам выпустит сертификат.

**И сразу после этого — четыре места, где старый адрес остаётся зашитым.**
Это самая частая причина, по которой «домен подключили, а приложение
сломалось»:

1. **Vercel → переменная `NEXT_PUBLIC_APP_URL`** — на новый адрес. Из неё
   собираются ссылки-приглашения и QR-код.
2. **Telegram, webhook бота** — переустановить на `https://<новый
   домен>/api/telegram/webhook`. Пока не переустановлен, бот молчит.
3. **Telegram, BotFather → `/setdomain`** — новый домен, иначе кнопка входа
   через Telegram перестанет пускать.
4. **cron-job.org** — три задания (утреннее напоминание, вечернее,
   персональный отчёт) зовут приложение по старому адресу.

Прежний адрес `*.vercel.app` продолжит работать — он не отключается, так
что откатиться можно в любой момент.

## 5. Как человек ставит приложение на телефон

**Android (Chrome).** Открыть сайт → браузер сам предложит «Установить
приложение», либо меню ⋮ → «Установить приложение». Появится ярлык,
приложение откроется на весь экран.

**iPhone (только Safari).** Открыть сайт в Safari → кнопка «Поделиться» →
«На экран "Домой"». В Chrome на iPhone этого пункта нет — Apple разрешает
установку только из Safari. Об этом стоит написать прямо в приглашении,
иначе половина людей не найдёт.

**Что отличается на iPhone.** Push-уведомления в установленном
веб-приложении Apple разрешила, но не в браузере, и работают они хуже
андроидных. Поэтому напоминания у нас идут через Telegram — это надёжнее и
работает одинаково везде.

## 6. Обёртка для магазинов приложений — не сейчас

Если однажды понадобится попасть в App Store и Google Play, есть два пути:

**Обёртка вокруг того же сайта** (Capacitor, Bubblewrap). Код не
переписывается, приложение остаётся одно. Дней пять работы плюс возня с
подписями и проверками.

**Настоящее нативное приложение** (React Native, Flutter). Второй проект,
который придётся развивать параллельно с этим. Месяцы работы.

**Постоянные расходы магазинов:** Apple — 99 $ в год, Google — 25 $
единоразово. Плюс проверка каждого обновления: сегодня правка выкладывается
за минуту, там ждать от суток.

**Вывод: не сейчас.** Всё, ради чего люди идут в магазин — ярлык на экране,
полноэкранный режим, работа без сети — уже есть в устанавливаемом
веб-приложении. Магазины понадобятся, только если приложение начнут искать
именно там.

## 7. Итог: что делать по порядку

1. Довести приложение до состояния, когда его не стыдно показать (идёт сейчас).
2. Купить домен и привязать к Vercel — полчаса.
3. Пройти четыре места из раздела 4, где зашит старый адрес.
4. Сделать 2–3 скриншота и добавить в манифест — витрина установки станет полноценной.
5. Проверить установку на Android и на iPhone по разделу 17 `CHECKLIST_TESTING.md`.
6. К магазинам приложений вернуться, когда будет повод.
