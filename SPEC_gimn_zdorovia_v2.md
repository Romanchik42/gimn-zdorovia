## БЛОК 0. Обзор проекта

### 0.1. Что это

**Гимн.здоровья** — сокращение от **«гимнастика для здоровья»**. Эта
расшифровка обязательна на лендинге, в онбординге и в разделе
«О приложении» — название не должно читаться как «гимн» (песня).

Веб-приложение (PWA) + Telegram-бот для двух категорий пользователей:

1. **Пациенты с болезнью Бехтерева (анкилозирующий спондилит)** —
   ежедневная реабилитационная гимнастика с автономной адаптацией
   программы под диагностику, побочные эффекты и прогресс.

2. **Обычные пользователи, работающие с телом** — похудение, набор
   мышечной массы, поддержание формы с рационом питания из доступных
   продуктов и циклической программой тренировок по группам мышц.

Оба режима работают в **одном приложении**. При первом входе пользователь
выбирает режим, проходит диагностику или анкету — дальше система ведёт
его автономно, но в любой момент он может собрать свою тренировку вручную.

Цель MVP — за 3 месяца после запуска получить 100+ активных пользователей
(3+ занятия в неделю) с retention > 40% на 30-й день.

## БЛОК 1. User Stories

### US-01. Пациент с Бехтерева регистрируется и проходит диагностику

**Как** пациент с болезнью Бехтерева,
**я хочу** пройти первичную диагностику,
**чтобы** приложение подобрало мне индивидуальную программу.

**Сценарий:**
1. Открываю https://gimn-zdorovia.vercel.app.
2. Вижу на лендинге: «Гимн.здоровья» и под ним — «Гимнастика для здоровья».
3. Кликаю «Войти через Telegram» → Telegram Login Widget → подтверждаю.
4. `/onboarding/welcome`: короткий экран — что это за приложение, расшифровка названия, медицинский дисклеймер, кнопка «Понятно».
5. `/onboarding/mode`: выбираю «Реабилитация Бехтерева».
6. `/onboarding/behtereva` — 5 экранов диагностики:
   - Тест Шобера (см, или «не знаю»)
   - Боковой наклон (см влево/вправо, или «не знаю»)
   - Ротация позвоночника (градусы, или «не знаю»)
   - Где болит сейчас (мультивыбор: плечо, шея, поясница, грудной отдел, ноги, таз, нигде)
   - Скованность утром (мало / средне / много) + давление в норме (да/нет)
7. `/onboarding/theme`: выбираю тему оформления.
8. `/app` — запускается ознакомительный тур (US-11).

**Критерии приёмки:**
- [ ] Каждый шаг диагностики можно пропустить («не знаю»).
- [ ] Ответы сохраняются в `user_diagnostics` с timestamp.
- [ ] Система рассчитывает `intensity_level` (low/medium/normal) и `focus_joints`.
- [ ] Повторная диагностика доступна раз в 30 дней.
- [ ] Медицинский дисклеймер показан до начала диагностики.

### US-02. Пользователь общей формы заполняет анкету

**Как** обычный пользователь,
**я хочу** быстро заполнить анкету,
**чтобы** получить программу тренировок и меню.

**Сценарий:**
1. Регистрация → `/onboarding/welcome` → `/onboarding/mode` → «Общая форма».
2. `/onboarding/general` — анкета:
   - Пол (м/ж), возраст, вес (кг), рост (см)
   - Цель: похудеть / набрать массу / поддерживать форму
   - Активность: сидячий / лёгкий / средний / высокий / очень высокий
   - Сложность: новичок / средний / продвинутый
   - Дни для тренировок (мультивыбор Пн-Вс)
3. Выбор темы → `/app` → ознакомительный тур.

**Критерии приёмки:**
- [ ] Zod-валидация: вес 30-300 кг, рост 100-250 см, возраст 14-100.
- [ ] Формула Миффлина-Сан-Жеора считает BMR → TDEE → целевые калории.
- [ ] Программа собирается по циклу (БЛОК 5.4).
- [ ] Меню подбирается под калораж ±5%.

### US-03. Пользователь выполняет тренировку

**Как** пользователь,
**я хочу** видеть каждое упражнение с GIF, техникой и кнопками отметки,
**чтобы** заниматься самостоятельно.

**Сценарий:**
1. `/app` → карточка «Сегодня: Позвоночник, 35 мин» → «Начать».
2. `/app/workout/[id]` — упражнения в порядке: **дыхание → разминка+самомассаж → основные → растяжка**.
3. Универсальная карточка (одна форма для всех упражнений):
   - GIF/картинка со стрелочками направления
   - Название, длительность или повторения
   - Описание техники
   - Кнопки: [✅ Сделал] [⚠️ Плохо] [❌ Пропустить]
4. Нажимаю кнопку → **звучит короткий звук** (если включены) → автопереход через 500 мс.
5. Финал: «Тренировка завершена! Сделано 11 из 12» + победный звук.

**Критерии приёмки:**
- [ ] Одна универсальная карточка на все упражнения.
- [ ] Кнопки ≥ 56px высотой.
- [ ] GIF lazy-load со Skeleton.
- [ ] Возврат к предыдущему упражнению стрелкой «назад».
- [ ] Частичная тренировка сохраняется при выходе.
- [ ] Звук проигрывается по настройкам пользователя (набор + громкость).

### US-04. Система реагирует на побочные эффекты

**Как** пациент с Бехтерева,
**я хочу** сообщить о плохом самочувствии,
**чтобы** получить безопасный совет и адаптацию тренировки.

**Сценарий:**
1. Кнопка «⚠️ Плохо» → модалка «Что случилось?»:
   - Головная боль / давление
   - Судорога в мышце
   - Острая боль в суставе
   - Тошнота / головокружение
   - Просто тяжело (без симптомов)
   - Другое
2. Выбираю → система показывает советы из Decision Tree (БЛОК 5.2).

- [ ] Правила хранятся в БД (`side_effect_rules`), не в коде.
- [ ] 3 побочки за неделю → баннер «Рекомендуем консультацию врача-ревматолога».

### US-05. Пользователь собирает свою тренировку ⭐ НОВОЕ

**Как** пользователь, который сегодня хочет тренировать другую группу мышц,
**я хочу** собрать собственную тренировку вместо плановой,
**чтобы** заниматься тем, чем хочу, а не только тем, что предложил план.

**Критерии приёмки:**
- [ ] Конструктор собирает корректную структуру занятия (всегда есть дыхание и растяжка).

- [ ] Шаблон сохраняется в `user_custom_workouts` и доступен с любого устройства.
- [ ] Для Бехтерева противопоказанные упражнения визуально отличаются и требуют подтверждения.

### 2.2. Ключевые изменения в `users` (версия 2.0)

```sql
CREATE TABLE IF NOT EXISTS users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  telegram_id BIGINT UNIQUE,
  telegram_username VARCHAR(100),
  email VARCHAR(200) UNIQUE,
  name VARCHAR(100) NOT NULL,
  gender VARCHAR(10) CHECK (gender IN ('male', 'female')),
  birth_date DATE,
  mode VARCHAR(20) NOT NULL CHECK (mode IN ('behtereva', 'general')),

  -- Оформление
  theme VARCHAR(20) NOT NULL DEFAULT 'sage'
    CHECK (theme IN ('sage', 'terracotta', 'ocean')),
  auto_theme BOOLEAN NOT NULL DEFAULT FALSE,

  -- Звук (НОВОЕ в 2.0)
  sounds_enabled BOOLEAN NOT NULL DEFAULT TRUE,
  sound_pack VARCHAR(20) NOT NULL DEFAULT 'soft'
    CHECK (sound_pack IN ('soft', 'energetic', 'minimal', 'none')),
  sound_volume INT NOT NULL DEFAULT 70 CHECK (sound_volume BETWEEN 0 AND 100),

  -- Напоминания
  morning_reminder_time TIME NOT NULL DEFAULT '07:00',
```

### 2.4. Генерация реферального кода

**Файл:** `src/lib/referral/code-generator.ts`

```typescript
// Алфавит без похожих символов: без 0/O, 1/I/L
const ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';
const CODE_LENGTH = 6;

export function generateReferralCode(): string {
  let code = '';
  const bytes = crypto.getRandomValues(new Uint8Array(CODE_LENGTH));
  for (let i = 0; i < CODE_LENGTH; i++) {
    code += ALPHABET[bytes[i] % ALPHABET.length];
  }
  return code;
}
```

Коллизии: при INSERT ловим `unique_violation` и перегенерируем (до 5 попыток).
Пространство: 31^6 ≈ 887 миллионов комбинаций — для MVP с запасом.

## БЛОК 3. API Endpoints

### 3.1. POST `/api/workout/custom` — сборка своей тренировки

**Body:**
```json
{
  "focus": "chest",
  "duration_min": 30,
  "intensity": "medium"
}
```

**Логика:**
1. Получить `user.mode` и последнюю диагностику/анкету.
2. Распределить время по структуре занятия:
   - breathing: 10% времени
   - warmup: 20%
   - main: 50%
   - stretch: 20%
3. Для каждой части подобрать упражнения из `exercises` с фильтрами:
   - `mode IN (user.mode, 'both')`
   - `target_joint = focus` (для main), любые для breathing/stretch
   - `level <= user_difficulty` (для general) или по `intensity` (для behtereva)
4. Пометить упражнения с противопоказаниями флагом `warning: true` +
   текстом предупреждения (НЕ исключать!).
5. Вернуть:
```json
{
  "success": true,
  "data": {
    "exercises": [
      {
        "id": "uuid",
        "name": "Дыхание животом",
        "type": "breathing",
        "duration_sec": 120,
        "order": 1,
        "warning": null
      },
      {
        "id": "uuid",
        "name": "Отжимания от пола",
        "type": "main",
        "repetitions": 12,
        "order": 5,
        "warning": "Не рекомендуется при боли в плече"
      }
    ],
    "total_duration_min": 31
  }
}
```

### 3.2. POST `/api/workout/custom/save` — сохранение шаблона

**Body:**
```json
{
  "name": "Моя грудь-день",
  "focus": "chest",
  "duration_min": 30,
  "intensity": "medium",
```

### 3.3. POST `/api/plan/update` — изменение недельного плана

**Body:**
```json
{
  "days": [
    {"day_of_week": 1, "focus": "chest", "duration_min": 40, "intensity": "medium", "is_rest_day": false},
    {"day_of_week": 2, "focus": "legs", "duration_min": 40, "intensity": "medium", "is_rest_day": false},
    {"day_of_week": 7, "focus": null, "is_rest_day": true}
  ]
}
```

**Логика:**
1. Валидация: все 7 дней присутствуют.
2. Проверка «две одинаковые группы подряд» → возвращаем `warnings[]`, но сохраняем.
3. Проверка «нет дней отдыха» → `warnings[]`, но сохраняем.
4. UPSERT в `user_week_plan`, `is_custom = true` для изменённых дней.
5. Ответ: `{ success: true, data: { saved: 7, warnings: ["Грудь в Пн и Ср подряд — мало отдыха"] } }`

### 3.6. POST `/api/cron/personal-report` — персональный отчёт

**Заголовок:** `Authorization: Bearer ${CRON_SECRET}` (проверять обязательно!).

**Логика:**
1. Выбрать пользователей с `next_report_date = CURRENT_DATE`.
2. Для каждого:
   - Определить `period_number` (сколько отчётов уже было + 1)
   - Собрать данные за последние 30 дней из `user_progress`, `user_workouts`, `side_effect_events`
   - Применить правила адаптации (БЛОК 5.5)
   - INSERT в `personal_reports`
   - Отправить в Telegram
   - Обновить `users.next_report_date = next_report_date + 30 дней`
3. Логировать в `notifications_log`.

**Важно:** крон запускается **каждый день в 09:00**, но обрабатывает только
тех, у кого сегодня «день икс». Так каждый получает отчёт в свою дату.

### 5.1. Формула расчёта калорий (Миффлин-Сан-Жеор)

```typescript
export function calculateBMR(
  gender: 'male' | 'female',
  weightKg: number,
  heightCm: number,
  ageYears: number
): number {
  const base = 10 * weightKg + 6.25 * heightCm - 5 * ageYears;
  return gender === 'male' ? base + 5 : base - 161;
}

const ACTIVITY_MULTIPLIERS = {
  sedentary: 1.2,
  light: 1.375,
  medium: 1.55,
  high: 1.725,
  very_high: 1.9,
} as const;

export function calculateTDEE(bmr: number, activity: keyof typeof ACTIVITY_MULTIPLIERS): number {
  return Math.round(bmr * ACTIVITY_MULTIPLIERS[activity]);
}

export function calculateTargetCalories(tdee: number, goal: 'lose' | 'gain' | 'maintain'): number {
  if (goal === 'lose') return Math.round(tdee * 0.8);
  if (goal === 'gain') return Math.round(tdee * 1.15);
  return tdee;
}
```

### 5.2. Decision Tree — реакция на побочки

Хранится в БД (`side_effect_rules`), не в коде.

| Симптом | Совет пользователю | Следующая тренировка |
|---------|---------------------|----------------------|
| `pressure_up` | Прерви на 5 мин. Сядь с приподнятой головой. Измерь давление. Пей воду мелкими глотками. | `reduce_intensity_20` |
| `headache` | Отдохни 3 мин. Проверь осанку. Самомассаж основания черепа (точка GB20) — 1 минута. Пей воду. | `reduce_intensity_20` |
| `cramp` | Прерви упражнение. Медленно растяни мышцу, держи 30 сек. Пей воду с электролитами. Проверь технику. | `lighter_only` |
| `joint_pain` | Останови это упражнение. Острая боль — сигнал «стоп». Мы исключим его из следующей тренировки. | `skip_exercise` + `skip_joint` |
| `nausea` | Останови тренировку. Отдохни 15 минут, подыши. Если не проходит — обратись к врачу. | `lighter_only` |
| `just_hard` | Нормально, если тяжело — значит работаешь. Снизим нагрузку в следующий раз. | `reduce_intensity_10` |

**Правило «врач»:** если за 7 дней ≥ 3 события с симптомами (кроме `just_hard`) —
показываем баннер: «За неделю ты несколько раз отмечал плохое самочувствие.
Рекомендуем консультацию врача-ревматолога.» Баннер скрывается по кнопке
«Понятно», но возвращается при новом триггере.

### 5.5. Персональная адаптация программы (от даты регистрации) ⭐ ИЗМЕНЕНО

**Было в 1.0:** отчёт всем 1-го числа месяца.
**Стало в 2.0:** отчёт каждые 30 дней от даты регистрации конкретного человека.

**Как работает:**
1. При регистрации: `registered_at = now()`, `next_report_date = today + 30 дней`.
2. Крон `/api/cron/personal-report` крутится **каждый день в 09:00**.
3. Выбирает пользователей с `next_report_date = CURRENT_DATE`.
4. Для каждого собирает данные за прошедшие 30 дней и применяет правила:

| Условие | Действие | Текст рекомендации |
|---------|----------|--------------------|
| Прогресс есть + занятий ≥ 4/нед | Усложнить: +2 упражнения уровня выше | «Отлично идёшь. Со следующей недели добавим пару упражнений посложнее.» |
| Прогресс есть + занятий 2-3/нед | Оставить | «Стабильно. Программа остаётся прежней — она тебе подходит.» |
| Прогресса нет + занятий ≥ 4/нед | Сменить фокус | «Занимаешься регулярно, но показатели стоят. Меняем акцент: добавим работу над [другой зоной].» |
| Занятий < 2/нед | Упростить + мотивация | «Получается реже, чем хотелось. Сделаем программу короче — 20 минут вместо 40. Главное — регулярность.» |
| Побочек ≥ 5 за период | Снизить интенсивность + врач | «Несколько раз было плохое самочувствие. Снижаем нагрузку и рекомендуем показаться врачу.» |

5. Сохраняем в `personal_reports`, отправляем в Telegram.
6. `next_report_date += 30 дней`.

**В приложении** на `/app/progress` показываем: «Следующий отчёт: 17 октября».

## БЛОК 7. Логотип и рекламные материалы ⭐ НОВОЕ

### 7.1. Концепция логотипа

**Название:** Гимн.здоровья
**Расшифровка:** гимнастика для здоровья
**Ощущение:** движение, восстановление, спокойствие. Не медицина, не фитнес-качалка.

**Знак (символ):**
Стилизованная фигура человека в наклоне вперёд — базовое движение
реабилитационной гимнастики (тест Шобера). Линия спины плавно
изгибается и переходит в дугу, которая читается и как позвоночник,
и как восходящая линия роста.

Альтернативная концепция: **три дуги разной длины**, растущие вверх —
позвоночник + прогресс + дыхание. Абстрактно, легко масштабируется,
хорошо работает в иконке 48×48.

**Требования к знаку:**
- Читается в размере 32×32 px (иконка в браузере)
- Работает в одном цвете (для печати, водяных знаков)
- Не содержит мелких деталей и текста внутри
- Перекрашивается под три темы через `currentColor`

### 7.2. Что кот-код должен подготовить

## Приложение D. Изменения после v2 (GIMN-007…010)

Структура, которая изменилась по сравнению с блоками выше. Где есть
расхождение — действует это приложение.

### D.1. Вход — только Telegram (заменяет email-вход из 3.1)
- `/auth/login` и `/auth/register` — один экран: виджет Telegram, при его
  недоступности (5 с) — кнопка «Войти через Telegram» в бота; описание
  приложения и дисклеймер. Email-формы и `POST /api/auth/register` удалены.
- `/tg?next=…&ref=…` — вход для всех кнопок бота (Telegram Web App):
  `POST /api/auth/telegram-webapp` проверяет initData (HMAC «WebAppData»).
- Аккаунт по email с привязанным Telegram входит через Telegram в свою же
  учётку (одноразовая ссылка без письма).
- Почта и телефон — в профиле, по желанию, НЕ для входа (`users.email`, `users.phone`).

### D.2. Схема БД
- 0012 `telegram_chats` (chat_id, home_message_id, workout_message_ids) —
  RLS без политик, только service_role.
- 0013 `users.phone`, `users.workout_length` (short|medium|full, NULL — по
  диагностике), `users.avatar`; `side_effect_events.reminded_at`; CHECK на
  symptom дополнен `just_hard` (раньше «Просто тяжело» не сохранялось).
- Картинки упражнений — `exercises.gif_url` = `/exercises/<slug>.gif`
  (источники: `docs/IMAGE_SOURCES.md`), без картинки — знак типа упражнения.

### D.3. Тренировка дня
- Длина: короткое 4-5 упр., среднее 7-8, полное — весь план (±10% к минутам
  плана). По умолчанию: тяжёлая диагностика (intensity low) — короткое, иначе
  среднее. Выбор — в настройках и перед первой отметкой (`POST /api/workout/length`).
- Структура в любой длине: дыхание, разминка, основное, растяжка — каждая
  часть хотя бы одним безопасным упражнением.
- Недельная адаптация: упражнения с ≥2 отметками ❌/⚠️ за прошлую календарную
  неделю заменяются на аналог той же зоны и части, не сложнее; число — то же.
- «В прошлый раз здесь было: [симптом]. Будьте осторожнее.» — один раз, когда
  упражнение снова на экране (`POST /api/workout/reminded`).

### D.4. Бот
- Чистый чат: /start и произвольный текст удаляются; одно «домашнее» сообщение
  с кнопкой; после регистрации оно удаляется — остаётся кнопка «Открыть» у поля
