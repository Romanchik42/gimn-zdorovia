БЛОК A — ПЕРЕКЛЮЧЕНИЕ РЕЖИМОВ (гибрид «посмотреть / заниматься»)
═══════════════════════════════════════════════════════════════════

ЦЕЛЬ: пользователь (сейчас видит только свой режим) может открыть другой
режим — либо ПОСМОТРЕТЬ (без анкеты, без записи), либо ЗАНИМАТЬСЯ (заполнить
анкету режима, вести программу). Данные ОБОИХ режимов хранятся раздельно и
НЕ теряются при переключении.

A1. МОДЕЛЬ ДАННЫХ (ключевое — сделать аккуратно, миграция):
   Сейчас mode — одно поле, режим один. Нужно поддержать несколько активных
   режимов на пользователя, с раздельным прогрессом. Реши по факту разведки,
   но целевая схема:
   - Новая таблица user_modes: id, user_id, mode ('behtereva'|'general'),
     is_active (bool — занимается ли реально), activated_at, last_used_at.
     Одна строка на (user_id, mode). RLS: своё.
   - users.mode оставить как «текущий выбранный режим» (какой показывается
     сейчас) — для обратной совместимости; или users.current_mode.
   - Привязать к режиму данные, которые различаются: user_workouts,
     user_progress, user_meals, user_week_plan, user_custom_workouts,
     personal_reports, user_diagnostics (behtereva), user_profiles_general
     (general) — добавить колонку mode туда, где её нет и где данные
     режимо-зависимы. Существующие строки 2 реальных юзеров — проставить
     их текущий mode (бэкофилл), НЕ потерять.
   - НИЧЕГО не удалять при переключении. Переключение = смена current_mode,
     данные всех режимов лежат рядом.

A2. ПРОСМОТР ДРУГОГО РЕЖИМА (вариант «Посмотреть»):
   - В настройках раздел «Режимы занятий»: показать режим(ы), которыми
     пользователь ещё не занимается, карточкой:
       «Общая форма — похудение, набор массы, поддержание формы»
       [Посмотреть] [Заниматься]
   - ПОСМОТРЕТЬ → открывает тренировки/меню этого режима в режиме просмотра:
       * генерирует показательную тренировку/меню по дефолтам режима
         (без личной анкеты — усреднённый профиль),
       * НИЧЕГО не пишет в БД (ни user_workouts, ни feedback, ни progress),
       * сверху плашка «Режим просмотра — данные не сохраняются»,
       * кнопка «Начать заниматься этим режимом» → переводит в ветку A3.
   - Просмотр доступен и обратно (если занимается общим — посмотреть Бехтерева).

A3. НАЧАТЬ ЗАНИМАТЬСЯ ДРУГИМ РЕЖИМОМ (вариант «Заниматься»):
   - Нажал «Заниматься» (или «Начать заниматься» из просмотра) → сразу
     задаём вопросы/анкету ЭТОГО режима:
       * general → анкета общего режима (пол/возраст/вес/рост/цель/
         активность/сложность/дни) — та, что уже есть.
       * behtereva → диагностика Бехтерева (базовая 5 + предложение
         углублённой) — та, что уже есть.
   - После заполнения: создать строку user_modes (is_active=true), завести
     программу/план этого режима, НЕ трогая данные прежнего режима.
   - current_mode переключается на новый.

A4. ПЕРЕКЛЮЧЕНИЕ КОГДА ВЕДЁШЬ ОБА:
   - Если у пользователя 2 активных режима — на главном экране /app
     переключалка «Сегодня занимаюсь: [Бехтерева] [Форма]» (segmented).
     Меняет current_mode, показывает данные выбранного.
   - В настройках — тоже переключение + возможность посмотреть/подключить
     недостающий (если вдруг один).
   - Прогресс (/app/progress), история (/app/history), питание, план —
     показывают данные ТЕКУЩЕГО режима. Переключил — увидел другой набор,
     старый цел.

A5. ГЕНЕРАТОР И ПОДБОР:
   - Генерация тренировок, меню, адаптация, недельные замены, персональные
     отчёты — работают в разрезе current_mode. Убедиться, что данные одного
     режима не подмешиваются в другой (фильтр по mode везде, где выбираются
     user_workouts/progress/feedback/meals).
   - Крон personal-report: отчёт по каждому активному режиму пользователя
     отдельно (или по current_mode — реши проще, но данные не путать;
     если несколько активных — можно отчёт на каждый, пометив режим).
